# Deploy Nivaran on Render

This repository is a monorepo: the FastAPI app is in `backend/`, while it imports the AI engine from `AI/` and serves the frontend from `smart-grievance-frontend/frontend/`. Keep the Render service root at the repository root so all three folders are available.

## Deploy with the Blueprint

1. Push this repository to a Git provider that Render can access.
2. In Render, create a **Blueprint** and select this repository. Render reads `render.yaml` from the repository root.
3. Enter the admin registration ID, the eight department registration IDs, and the three Brevo SMTP secrets (`SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`) when Render prompts for the secret environment variables. Retrieve them from your ignored local `backend/.env`; do not add these values to Git or `render.yaml`. The Blueprint already sets `SMTP_HOST=smtp-relay.brevo.com` and `SMTP_PORT=587`.
4. Review the paid web service, PostgreSQL database, and 1 GB persistent uploads disk before approving Blueprint creation.
5. After the first deploy, open `/health` on the generated Render URL. The site is served from `/` and the API docs from `/docs`.

The Blueprint uses Render PostgreSQL for complaint records and a persistent disk mounted at `/var/data` for uploaded complaint images. Both are required to keep complaints and their photos across deploys. Render's free web services cannot attach persistent disks, and free Postgres expires after 30 days, so the Blueprint intentionally specifies persistent paid resources for stored user data.

## Before launch

- The initial remote PostgreSQL database is empty. Local SQLite users, complaints, and uploaded photos are not copied automatically.
- The app currently uses password authentication. Twilio OTP variables in the local `.env` are not needed by the deployed password-based login flow.
- `JWT_SECRET` is generated by Render. Keep the registration IDs, SMTP credentials, and database credentials in Render's environment, not in source files.
- `SMTP_FROM` must be a sender address verified in the Brevo account, and the same value is used in production, or Brevo rejects every notification.
- Review registration access before sharing the URL. Anyone with an officer or admin registration ID can register that role.
- Check the Render service logs and `/health` after deploy. If you change database schema later, create a deliberate migration before deploying it.

## VS Code

Open the repository root in VS Code and edit `render.yaml`. The `.python-version` file pins the native Python runtime to the 3.12 series. Install the Red Hat YAML extension for Blueprint validation and completion.
